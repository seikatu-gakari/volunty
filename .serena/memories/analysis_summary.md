# プロジェクト分析まとめ

## 分析概要
`spec_driven_template`プロジェクトの**Serena MCP分析結果**（2025年11月4日実施）

## プロジェクトの性質
- **テンプレート・ガイドプロジェクト**：実際のアプリケーション開発ではなく、開発手法の標準化
- **Speckit仕様駆動開発**：フィーチャーベースの計画・実装・管理ワークフロー
- **ドキュメント中心**：Markdownとスクリプトが主体、プログラミング言語のコードは最小限

## 技術的特徴
- **Bashスクリプト自動化**：手動作業を最小化する設計
- **GitHub Copilot統合**：AI支援を前提とした開発フロー
- **Git ブランチ規則**：`NNN-feature-name`による厳格な管理

## 開発者向け重要事項
1. **ブランチ名必須**：`001-`, `002-`等の接頭辞なしでは動作しない
2. **macOS/Linux前提**：Bash互換環境が必要
3. **段階的ワークフロー**：フェーズ0（計画）→フェーズ1（設計）→フェーズ2（タスク）
4. **自動更新**：Copilot指示ファイルは手動編集不推奨

## 特殊な側面
- **憲章プレースホルダー**：`.specify/memory/constitution.md`は未整備
- **Node.js記載**：`.gitignore`にあるがテンプレート用、実際は不使用
- **日英混在**：日本語メインだが技術用語は英語併記

## 推奨アプローチ
- Serena symbolsツールは主にBashスクリプトとMarkdownファイルに適用
- パターン検索で設定ファイルやテンプレートを探索
- メモリ情報を活用して効率的な分析・編集を実施
