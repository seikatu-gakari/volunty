# アーキテクチャ概要

## 1. システム全体像
- **ドメインの目的**: プロダクトが解決したい課題や提供価値を1段落で記述。
- **主要ユースケース**: エンドユーザー視点で代表的な業務フローを箇条書き。
- **コンテキスト図**: 外部サービスや依存システムとの関係を図解またはテキストで整理。

## 2. モジュール構成
- **高レベル構成図**: アプリケーション層やサービス層の境界を示す。
- **各モジュールの責務**: データアクセス、API、UI などの役割と依存関係を明記。
- **共有ライブラリ / 共通基盤**: 再利用部品やユーティリティの方針を記載。

## 3. データフローとストレージ
- **主要データモデル**: エンティティの概要、属性、整合性ルール。
- **入出力フロー**: 外部 API・バッチ・イベントなど、データの流れを図解。
- **保存戦略**: 使用予定のデータベース、キャッシュ、ファイルストレージと冗長化方針。

## 4. 非機能要件
- **パフォーマンス / スケーラビリティ**: 目標レスポンスタイム、処理件数、スケール方法。
- **セキュリティ / プライバシー**: 認証・認可・監査ログ・データ保護のルール。
- **運用 / 監視**: ログ収集、メトリクス、アラート、リリース手順。

## 5. テスト戦略
- **テストピラミッド**: ユニット、統合、E2E の役割と推奨ツール。
- **自動化ポリシー**: CI/CD で必須のテストと任意のテストを区別。
- **テストデータ管理**: フィクスチャ、シードデータ、モックの扱い。

## 6. 今後の課題と決定事項
- **未決事項**: 設計・技術選定で検討中のテーマ。
- **決定ログリンク**: `.github/knowledge-base/index.md` の Decision Log への参照を記載。
- **フィードバック窓口**: 問い合わせ先 Issue / Discussion / Slack など。
