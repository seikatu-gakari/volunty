# 公開前の待機リスト

未ログインの `/` はメールで開始通知を受け取る待機リスト導線に統一する。既存利用者・管理者の認証機能や直接URLへのアクセスは変更しない。登録で認証アカウントは作らず、この変更ではメール送信・配信サービス連携も行わない。

## 保存と安全対策

- `POST /api/waitlist` でサーバー側検証し、既存のPrisma接続で `t_waitlist_entry` に正規化メールと登録日時を保存する。
- メールは前後空白除去・小文字化して一意保存。重複時も初回と同じ成功応答を返し、登録の有無や登録日時を外部に漏らさない。
- 一般的なASCIIメールに対応。メール所有の検証は未実施のため、保存済みメールを本人確認済み会員として扱わない。
- メール一覧の公開APIはない。両テーブルはRLS有効かつ `PUBLIC` / `anon` / `authenticated` の権限を取消。アプリサーバーの既存DB接続のみが操作する。
- Origin確認・JSON/2KB上限・honeypotに加え、Vercelが上書きする `x-vercel-forwarded-for` を利用してIP単位に固定15分枠で10回まで。HMACを保存し、生IPは保存しない。複数サーバーでもDBの原子的UPSERTで共有する。
- レート制限の期限切れ行は次の正常な登録リクエストで削除する。アクセスが止まった場合は残るため、厳密な保存期限が必要なら別途運用上の定期削除を設定する。
- 分散ボットを完全に防ぐ仕組みではない。必要に応じてVercel側でWAF等を別途設定する。CAPTCHA/外部サービスは追加していない。
- 本番モードでVercel以外のホストや信頼できるIP/秘密値がない場合は503で停止する。自己ホスト対応では信頼できるプロキシの設計が必要。
