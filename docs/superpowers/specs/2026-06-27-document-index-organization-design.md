# ドキュメントインデックス整理設計

## 目的

`docs/index.md` を現在の作業ツリーに存在するドキュメントの全件カタログとして更新し、古い実装状況や検証日の記載を残さない。

## 対象

- `docs/index.md` 自身を除く `docs/` 配下の Markdown ファイル
- `specs/` 配下の Markdown・JSON ファイル
- 未コミットの追加・削除を含む現在の作業ツリー

## 構成

- ディレクトリ単位でセクションを分ける。
- 各表は「ファイル」「概要・位置づけ」の2列とする。
- 同一内容が複数パスに存在する場合も全パスを掲載し、複製であることを注記する。
- 削除済みファイルは掲載しない。

## 状態情報の扱い

- `docs/index.md` では「未実装」「実装済み」などの変化しやすい状態を独自に断定しない。
- 現在の実装・品質状況は `docs/quality/status.md` と `specs/features.json` を参照先として案内する。
- 各ファイルの概要は、現在の見出しと内容から要約する。

## 検証

- インデックス内の相対リンクがすべて実在することを確認する。
- 対象ファイル一覧とインデックス掲載先の差分がないことを確認する。
- `docs/index.md` 以外の既存ファイルは変更しない。
