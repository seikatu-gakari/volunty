# Volunty Test Completion Gate

## 概要

実装完了前に変更を分類し、必要な UT と E2E を追加・実行する。既存テストが通るだけでは、変更した振る舞いの検証にはならない。

**鉄則:** 必要なテストが不足または未実行なら、完了を宣言しない。

## 変更分類

ファイル種別だけでなく、変更した振る舞いと利用者への影響で判定する。

| 変更 | UT | E2E |
| --- | --- | --- |
| ドメインロジック、Server Action、バリデーション、状態遷移 | 必須 | ユーザーフローも変わる場合は必須 |
| 画面、フォーム、ルート、認証、権限、複数ロールのフロー | 分岐や変換ロジックがあれば必須 | 必須 |
| DB schema、migration、外部I/O | 決定的なロジックがあれば必須 | 実行経路が変わる場合は必須 |
| 振る舞いを維持するリファクタリング | 回帰UTを追加または更新 | 主要フローへ影響する場合は更新 |
| ドキュメント、instructions、テストのみ | 原則不要 | 原則不要 |

両方に該当する変更では、UT と E2E の両方を追加または更新する。不要と判断した区分は、最終報告に**適用外理由**を書く。

ユーザーに見えるUI変更では、通常E2Eに残る受入シナリオを `docs/pr-demo-video.md` の録画契約にも指定する。主viewportのテストが正確に1件選択され、15〜45秒の動作ビデオを生成できることを確認する。

## 完了ゲート

1. `git diff --name-only` と要件を読み、変更した振る舞いを列挙する。
2. 上表で UT/E2E を `必須` または `適用外` に分類する。
3. 既存テストが変更後の振る舞いを実際にassertしているか確認する。
4. 必要なテストを実装より先に追加し、期待した理由でREDになることを確認する。
5. 最小実装でGREENにし、全体検証を実行する。

**REQUIRED SUB-SKILL:** 新機能・バグ修正・振る舞い変更では `superpowers:test-driven-development` を使う。

## 検証コマンド

```bash
# 対象UT
cd app && npx vitest run <test-file>

# 全UT
cd app && npm test

# E2Eが必須の場合
make e2e
```

lint、型チェック、buildは `volunty-dev-commands` に従う。E2E環境を起動できない場合は、実行コマンド、失敗理由、残タスクを報告し、完了を宣言しない。

## 完了報告

次の表を必ず埋める。

| 区分 | 判定 | 追加・更新したテスト | RED/GREEN | 最終結果 |
| --- | --- | --- | --- | --- |
| UT | 必須 / 適用外 | パスまたは適用外理由 | 確認結果 | コマンド結果 |
| E2E | 必須 / 適用外 | パスまたは適用外理由 | 確認結果 | コマンド結果 |
| PR demo | 必須 / 適用外 | spec、tag、viewportまたは適用外理由 | 契約・録画結果 | `demo-video` 結果 |

## レッドフラグ

- 「小さい変更なのでテスト不要」
- 「既存テストが通ったので追加不要」
- 「UTで通ったのでブラウザフローは未確認でよい」
- 「E2E環境がないが完了とする」

これらを考えた場合は判定へ戻り、変更した振る舞いをassertするテストがあるか確認する。
