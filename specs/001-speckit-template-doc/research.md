# 調査結果

## 判断: 憲章ゲートは情報提供として扱う
- **理由**: `.specify/memory/constitution.md` には見出しのみが存在し、強制力のある原則がない。独自に方針を作るのではなく、現状が暫定であることをドキュメントに明記する必要がある。
- **検討した代替案**:
  - README に暫定的なガバナンスルールを記述する → 公式更新と衝突する恐れがあるため却下。
  - 憲章への言及を省略する → ゲート表示の理由が伝わらず混乱を招くため却下。

## 判断: GitHub Copilot のエージェントコンテキスト更新を強調する
- **理由**: リクエストで Copilot を主要エージェントと明示しているため、`.specify/scripts/bash/update-agent-context.sh copilot` による `.github/copilot-instructions.md` 更新手順を README で説明する必要がある。
- **検討した代替案**:
  - エージェント一般の説明にとどめる → Copilot へ直結する手順が不足するため却下。

## 判断: Speckit のライフサイクルコマンドを網羅的に記載する
- **理由**: 計画の雛形作成、調査・設計フェーズ、タスク生成までの一連の流れを理解してもらう必要がある。`setup-plan.sh --json`、成果物の手動編集、`update-agent-context.sh`、`speckit.tasks` 等を列挙する。
- **検討した代替案**:
  - 計画作成のみに範囲を絞る → 要望が仕様駆動開発の全体像に言及しているため却下。
